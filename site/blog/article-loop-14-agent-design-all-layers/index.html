    エージェント設計の全レイヤー — プロンプト→グラフまで + note販売ノウハウ¶

    元ファイル: 非エンジニアでもわかる、AIエージェント設計の教科書.md（X @ai_ai_ailover, 37万再生）、【AI丸投げOK】10日でnote0-1...md, 【AI丸投げOK】Claude1400万.md`（X @kakechin10）

    概要¶

    非エンジニア向けに「コンテキスト→ハーネス→ループ→グラフ」の設計レイヤーを解説。さらにnote販売の実践ノウハウ（無料→有料転換術、AIとの協業手順）を追記。全5枚の設計レイヤーは競合する概念ではなく積み重なった設計層である。

    1. AIエージェントの9つの設計レイヤー¶

    「新入社員」で考えれば全部わかる：

    エイジェン 人間への比喩
    プロンプト 社員に渡す一回の依頼文
    コンテキスト 社員の机の上に置く資料
    ハーネス 社員が働くオフィスの道具・ルール・環境
    ループ 作業＋確認＋修正を繰り返す業務サイクル
    グラフ 部署・担当者・承認経路を含む組織図
    スペック 完成品の仕様書
    スキル 業務マニュアル
    ツール 社員が使えるPCやソフト
    メモリ 過去の引き継ぎノート

    流行語に振り回されない：これらは競合する概念ではなく、AIを実務で働かせるための積み重なった設計レイヤー。

    2. （1）プロンプトエンジニアリング — 「一回の指示」を設計する¶

    よいプロンプトの基本構造¶

    1. 目的: 何をしたいのか。「記事を書く」→「読者が記事を直後に一つ行動を始められるようにする」
    2. 対象者: 誰向けか。初心者と専門家では説明量・専門用語異なる
    3. 背景: なぜこの作業が必要か（←文脈理解でAIの細判断が向上）
    4. 制約: 文字数、禁止事項、資料、期限、調子etc.
    5. 出力形式: 見出し、箇条書き、JSON等完成形指定
    6. 評価基準: 何を満たせば「よい出力」か（Anthropic推奨）

    例：

    ADHDの診断を受けたばかりの成人向けに、生活上の困りごとを軽減する30日ロードマップ記事を作成してください。精神論ではなく心理学・行動科学・医療機関オープン情報を根拠に。医療行為や服薬について断定せず。初日は5分以内で実行できる内容にし、徐々に難易度を上げてください。

    クリップトエンジニアリングの限界¶

    • 最新情報がない → どんな命令も正しい情報は出ない
    • 会社の固有情報なし → 独自提案できない
    • ツールがなければ説明だけ
    • 一回目ミスの自動修正仕組みなし → 人手が必要なループになる

    3. （2）コンテキストエンジニアリング — 「何を知った状態で」という設計¶

    プロンプトが「何をするか」、コンテキストは「何を知った状態でやってほしいか」。

    コンテキストに含まれるもの（記事作成例）¶

    過去の記事、読者属性、自社商品・ルール、参考論文、禁止表現、ニュース、競合記事、過去の会話、途中原稿、検索結果、他AI調査結果etc.

    「たくさん渡せば良し」は間違い¶

    情報が増えるほど：古い指示と衝突→重要情報が埋もれる→無関係な文章に注意を奪われる。Anthropic「コンテキストは有限資源」。

    五つの基本操作¶

    1. 選ぶ: 今の作業に必要なものだけ
    2. 並べる: ルール→依頼→資料の順で配置
    3. 圧縮する: 長い会話/資料を要約し重要部分のみ
    4. 分離する: 調査・執筆・校正を分ける
    5. 更新する: 古い情報や間違えたメモを残しつけない

    コンテキストパック（実務的アプローチ）¶

    article-project/
├── brief.md         ← 今回の記事の目的
├── audience.md      ← 読者像
├── style-guide.md   ← 文体・禁止表現
├── source-policy.md ← 情報源ルール
├── good-examples/   ← 過去の優良記事
├── research/        ← 今回の調査結果
└── current-draft.md ← 現在の原稿

    4. （3）ハーネスエンジニアリング — 「頭脳」と現実の「身体」を接続する¶

    英語 Harness = 馬具・安全帯・制御装置。「AIの頭脳（モデル）」を実際仕事に繋ぐ物理・作業環境全体。

    ハーネスに含まれるもの¶

    システムプロンプト、AGENTS.md/CLAUDE.md、検索/計算/ファイル操作ツール、MCP/外部接続、作業用フォルダ、サンドボックス、読み書き権限、ネットワークアクセス、状態保存、エラー再試行、ログ・トレース、テスト・評価基準、人間の承認ポイント、中断再開机制etc.

    「文章でお願い」→プロンプト。仕組みとして守らせる→ハーネス¶

    OpenAI: 巨大なAGENTS.mdに書かず短いものを目次として使い詳細は構造化ドキュメント群に分ける指示ファイル「絶対削除するな」と書くことと、システム上本当に削除できないのは別

    5. （4）ループエンジニアリング — 自動フィードバックサイクルの設計¶

    基本形¶

    目的を確認 → 行動 → 結果観察 → 成功条件と比較 → 失敗→修正 → もう一度行動

    ループの4段階（LangChain分類）¶

    1. Agent Loop: AIツール使用して作業完了
    2. Validation Loop: 出力採点、不合格→リトライ
    3. Event-driven Loop: スケジュール/Webhook/新規ファイルトリガーで自動実行（morning brief等）
    4. Improvement Loop: ログ分析→プロンプト・ツール・評価基準自体を改善

    「終了条件」が最重要¶

    • 全必須項目に合ったら終了
    • 最大3回まで修正
    • 3连続で点数上がらなければ人間に確認
    • 引用元未確認主張は削除
    • 外部公開/送信/削除→人間の承認必要
    • 予算/時間上限を超えたら停止

    6. （5）グラフエンジニアリング — 複数工程の設計図¶

    ループは単純な循環グラフ。「次はグラフ」≒「ループ否定」ではない。

    シンプルなループ vs グラフ¶

    [ループ]             [グラフ]
執筆→確認→修正       依頼→要件整理→海外調査→国内調査→論文調査
確認→修正              ↓                ↓          ↓         ↓
確認                    └→情報統合→（↓検証→✗→該当工程へ戻る）
                              →合→完成

    グラフ設計の基本¶

    • 確実性が必要な→固定。創造性が必要な→AI裁量
    • AIを複数使えば優秀になるわけではない → 単純な組み合わせ可能なパターンを推奨

    7. Appendix: note販売の実践ノウハウ¶

    ソース動画要約＋@kakechin10 (@ai_ai_ailover)のXポスト統合：

    売れるnoteの作り方¶

    • ジャンル: 自分の経験ベースかつ「HARM法則」（健康/キャリア/人間関係/お金）に当てはまるものから選定。日常の小さな不満→「〇〯の仕組みの作り方」な名詞型テーマに変換
    • 価格設定: 初心者は相場合わせ（980〜3000円）。同じテーマ競合が多い＝「お金を払う需要がある証拠」
    • AI執筆手順: キャラ設定→目次作成(60点)→人間修正(120点)→本文分割出力→手動装飾・追記（体験談・見出し・太字・画像）

    無料→有料転換の鉄則¶

    • まず「有料部分」から書く（解決策・手順中心）
    • 次に「無料部分」（共感＋問題提起。「今買わないと損だ感」）
    • 有料ラインは絶妙なタイミング（下にしすぎると購入率激減。返金設定→オフ推奨）
