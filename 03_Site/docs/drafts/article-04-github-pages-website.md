# GitHub Pagesで無料アフィリエイトサイトを作る方法｜WordPressなしで始める実践メモ

※この記事には広告・アフィリエイトリンクを含む場合があります。

## はじめに

アフィリエイトを始めようとすると、多くの場合、最初にWordPressやレンタルサーバーの話が出てきます。

もちろん、WordPressは本格的にブログやアフィリエイトサイトを運営するには便利です。

しかし、最初からレンタルサーバー代、独自ドメイン代、有料テーマ代を払うのは、少しハードルが高いと感じる人も多いと思います。

私自身も、最初はできるだけ無料で始める方法を考えました。

そこで候補になるのが、GitHub Pagesです。

GitHub Pagesを使えば、有料サーバーを契約しなくても、MarkdownやHTMLで作った静的サイトを公開できます。

この記事では、WordPressを使わずに、GitHub Pagesで無料アフィリエイトサイトを作る方法を、Ubuntu・Markdown・AI活用の視点から整理します。

---

## 結論：最初の実験サイトならGitHub Pagesで十分

結論から言うと、アフィリエイトを無料で小さく試す段階なら、GitHub Pagesで十分です。

特に、次のような人には向いています。

* 有料サーバーを契約せずに始めたい人
* 有料ドメインなしで試したい人
* Markdownで記事を書きたい人
* Obsidianのメモを記事化したい人
* UbuntuやLinux環境で作業したい人
* AIに記事下書きを作らせたい人
* noteやXと組み合わせて発信したい人
* まずは無料でアフィリエイト導線を試したい人

GitHub Pagesは、WordPressのような管理画面を持つブログシステムではありません。

基本的には、HTML、CSS、JavaScript、Markdownなどで作った静的サイトを公開する仕組みです。

そのため、会員登録機能、コメント機能、動的な検索機能、PHPやPythonによるサーバー側の処理は苦手です。

しかし、初期のアフィリエイトサイトに必要な次のようなページは十分に作れます。

* トップページ
* プロフィールページ
* 記事ページ
* 比較記事
* おすすめツール一覧
* 広告・アフィリエイト表記ページ
* noteやXへのリンク
* ASP比較記事
* 無料ツール紹介記事

最初から完璧なサイトを目指すより、まずは無料で記事を公開し、読者の反応を見ることが大切です。

## GitHub Pagesで作るサイトのイメージ

今回作る無料アフィリエイトサイトは、次のような構成を想定します。

```text
GitHub Pagesサイト
├── トップページ
├── プロフィール
├── 広告・アフィリエイト表記
├── Ubuntu・ローカルAIの記事
├── GitHub Pages運用の記事
├── AI副業に必要なツール記事
├── ASP比較記事
├── note活用記事
└── おすすめツール一覧
```

このサイトでは、いきなり商品を売り込むのではなく、まず自分の実体験を記事にします。

たとえば、次のような記事です。

* 50代からUbuntuでローカルAI環境を作ってみた
* OllamaとOpen WebUIでできること・できないこと
* Hermes AgentでObsidianを外部脳にする方法
* AI副業を始めるために必要なPC・サーバー・ツール
* GitHub Pagesで無料アフィリエイトサイトを作る方法
* 無料で始めるアフィリエイトASP比較
* AI記事作成でやってはいけないこと

このように、自分が実際に試した内容を中心にすれば、単なる広告サイトではなく、読者に役立つ実践記録になります。

## なぜWordPressではなくGitHub Pagesから始めるのか

WordPressには大きなメリットがあります。

記事の投稿、カテゴリー管理、デザイン変更、プラグイン導入、広告管理などがしやすいです。

本格的にブログ運営をするなら、WordPressは有力な選択肢です。

しかし、最初の段階では次のような負担もあります。

* レンタルサーバー代がかかる
* 独自ドメイン代がかかる
* WordPress本体の更新が必要
* プラグイン管理が必要
* セキュリティ対策が必要
* バックアップ設定が必要
* テーマ選びで迷いやすい
* 表示速度や広告配置にも気を使う

一方、GitHub Pagesは静的サイトなので、構成がシンプルです。

MarkdownやHTMLファイルを用意し、GitHubに反映すればサイトとして公開できます。

初期費用をかけずに、アフィリエイト記事の練習、SEOの確認、noteやXからの導線づくりを試せるのが大きなメリットです。

最初はGitHub Pagesで無料サイトを作り、記事が増えて収益化の方向性が見えてから、WordPressや独自ドメインを検討すればよいと思います。

## GitHub Pagesが向いている記事

GitHub Pagesは、次のような記事と相性がよいです。

| 記事タイプ     | 相性  | 理由                  |
| --------- | --- | ------------------- |
| 手順記事      | 高い  | Markdownで整理しやすい     |
| 比較記事      | 高い  | 表や見出しで構成しやすい        |
| 実践記録      | 高い  | Obsidianのメモから転用しやすい |
| ツール紹介     | 高い  | 内部リンクを作りやすい         |
| FAQ記事     | 高い  | 静的ページでも作りやすい        |
| 日記記事      | 中   | noteの方が向く場合もある      |
| 速報記事      | 低〜中 | 更新頻度が高いと管理が大変       |
| 会員制サイト    | 低い  | 静的サイトだけでは難しい        |
| コメント付きブログ | 低い  | 標準ではコメント機能がない       |

私の場合は、Ubuntu、ローカルAI、Obsidian、Hermes Agent、note運用、無料アフィリエイトのようなテーマを扱う予定なので、GitHub Pagesとの相性はかなり良いと考えています。

## トップページの役割

トップページでは、サイトの目的を短く伝えます。

たとえば、次のような内容です。

```text
このサイトでは、50代からUbuntu、ローカルAI、Obsidian、Hermes Agent、GitHub Pagesを使って、無料でAI活用と副業サイト運営に挑戦する実践記録をまとめています。
```

トップページに入れたい要素は次です。

* サイトのテーマ
* 誰に向けたサイトか
* 主な記事カテゴリ
* 最新記事へのリンク
* おすすめ記事へのリンク
* 広告・アフィリエイト表記ページへのリンク
* noteやXへのリンク

最初のトップページは簡単で構いません。

記事が増えてきたら、カテゴリー別に整理していけばよいです。

## プロフィールページの役割

アフィリエイトサイトでは、誰が書いているかが分かることも大切です。

特に、AIや副業のようなテーマでは、読者は「この人は実際に試しているのか」を見ます。

プロフィールページには、次の内容を入れます。

* 表示名
* サイトを始めた理由
* 扱うテーマ
* 実際に使っている環境
* noteやGitHub Pagesの運用方針
* 読者に約束すること
* 広告リンクの扱い方

たとえば、次のような書き方です。

```text
このサイトでは、実際にUbuntuやローカルAI環境を試しながら、作業記録、失敗談、無料ツールの使い方をまとめています。広告リンクを含む場合がありますが、公式情報や実体験を確認し、誇大表現を避ける方針で運営します。
```

本名や勤務先など、公開したくない個人情報は書く必要はありません。

公開する情報と非公開にする情報は、事前に分けておくべきです。

## 広告・アフィリエイト表記ページの役割

アフィリエイトサイトでは、広告リンクを含む可能性があることを分かりやすく示す必要があります。

そのため、早い段階で `disclosure.md` を作ります。

例文は次のとおりです。

```markdown
# 広告・アフィリエイト表記について

当サイトでは、記事内に広告・アフィリエイトリンクを含む場合があります。

リンク経由で商品やサービスを購入・申し込みいただいた場合、運営者に報酬が発生することがあります。

ただし、紹介内容は実際の利用経験、公式情報、調査内容をもとに作成し、読者に不利益となる誇大表現や根拠のない断定を避ける方針です。

価格、仕様、キャンペーン内容、成果条件は変更される場合があります。

実際に利用する場合は、必ず公式サイトで最新情報をご確認ください。
```

また、広告リンクを含む記事の冒頭にも、次の一文を入れます。

```markdown
※この記事には広告・アフィリエイトリンクを含む場合があります。
```

これは、読者の信頼を守るためにも重要です。

## GitHub Pagesで作る場合の手順

ここでは、GitHub Pagesで無料サイトを作る大まかな流れを整理します。

```text
1. GitHubアカウントを用意する
2. 新しいリポジトリを作る
3. docsフォルダを作る
4. index.mdを作る
5. profile.mdを作る
6. disclosure.mdを作る
7. 記事を3本程度作る
8. GitHub Pagesの公開元を設定する
9. 公開URLを確認する
10. Search Consoleに登録する
11. ASP登録へ進む
```

最初からデザインにこだわる必要はありません。

まずは、読者に役立つ記事が存在し、サイトの目的が分かる状態にします。

## GitHubリポジトリの作り方

GitHub上で新しいリポジトリを作ります。

リポジトリ名は、分かりやすい名前にします。

例：

```text
affiliate-free-ops
local-ai-affiliate-note
ai-sidejob-lab
```

GitHub PagesのURLは、通常、次のような形になります。

```text
https://ユーザー名.github.io/リポジトリ名/
```

すでにGitHub Pagesを使っている場合は、同じGitHubアカウント内に新しいリポジトリを作って、プロジェクトサイトとして公開できます。

## GitHub Pagesの公開元を設定する

GitHub Pagesでは、どのブランチ・どのフォルダを公開するかを設定します。

無料運用では、まず次の設定が分かりやすいです。

```text
Branch: main
Folder: /docs
```

この場合、`main` ブランチの `/docs` フォルダ内にあるファイルが公開対象になります。

そして、`docs_index.md` がトップページになります。

変更を反映したあと、数分待つと公開URLで確認できるようになります。

反映に少し時間がかかる場合があるため、すぐに表示されなくても慌てず確認します。

## ASP登録への導線

GitHub Pagesでサイトを作ったら、次にASP登録へ進みます。

ただし、サイトを作った直後に広告リンクだけを貼るのはおすすめしません。

まずは、次の状態を目指します。

```text
トップページがある
プロフィールページがある
広告表記ページがある
記事が3〜5本ある
サイトのテーマが分かる
誇大表現がない
個人情報が公開されていない
```

そのうえで、ASP登録へ進みます。

初期候補は次の3つです。

| ASP        | 向いているもの          |
| ---------- | ---------------- |
| 楽天アフィリエイト  | PC用品、書籍、日用品      |
| もしもアフィリエイト | Amazon・楽天系商品リンク  |
| A8.net     | サーバー、学習サービス、ツール系 |

最初は、楽天やもしもで書籍やPC周辺機器を自然に紹介し、A8.netでサーバーや学習サービスなどの案件を探す流れが分かりやすいです。

```text

↓

↓
広告表記ページを作る
↓

```

たとえば、次のような記事からA8.netへつなげられます。

* WordPressを使わず無料で副業サイトを作る方法

* noteとブログを組み合わせて収益導線を作る方法
* 無料で始めるアフィリエイトASP比較

CTAの文言は、強く売り込まず、次のようにします。

```text
ブログや無料サイトに合うサービス案件を探したい方は、A8.netで自分のテーマに合う広告があるか確認してみるとよいです。
```

## noteとXの使い方

GitHub Pagesだけで集客するのは、最初は難しいです。

そこで、noteとXを使います。

### noteの役割

noteでは、検索記事というより、体験談や読み物を書きます。

例：

* 50代からAI副業を始めようと思った理由
* UbuntuでローカルAI環境を作ってみた話
* AIに聞きながら作業したら、手順を覚えていなかった話
* 無料でアフィリエイトサイトを作る実験を始めた話

note記事の最後に、GitHub Pagesの記事へリンクします。

### Xの役割

Xでは、記事の要点を短く投稿します。

例：

```text
有料サーバーなしでアフィリエイトサイトを作る実験を始めました。

使うもの：
・GitHub Pages
・Obsidian
・Markdown
・AI下書き
・note
・ASP

まずは無料で小さく始めて、反応を見ながら改善します。
```

Xは、記事の反応を確認する場所として使います。

## GitHub Pages運用で注意すること

GitHub Pagesでアフィリエイトサイトを作る場合、次の点に注意します。

### 1. 個人情報を入れない

公開リポジトリで運用する場合、ファイルは外部から見えるものとして扱います。

次の情報は絶対に入れないようにします。

* 住所
* 電話番号
* 本名を出したくない場合の本名
* 銀行口座情報
* ASPの管理画面情報
* ログインID
* パスワード
* APIキー
* 秘密のメモ
* 未公開の個人情報

特に、AIエージェントにファイルを作らせる場合は、公開フォルダに個人情報が混ざらないように注意します。

### 2. 広告表記を忘れない

アフィリエイトリンクを含む記事には、広告・アフィリエイトリンクを含むことを明記します。

読者が広告だと分かる場所に書くことが重要です。

### 3. 誇大表現をしない

次のような表現は避けます。

* 必ず稼げる
* 誰でも簡単に月〇万円
* 完全放置で収益化
* これだけで稼げる
* 絶対おすすめ
* 公式より安いと断定
* 買わないと損

アフィリエイト記事では、読者に冷静に判断してもらえる書き方が必要です。

### 4. 商品情報を放置しない

価格、仕様、キャンペーン、成果条件は変わります。

記事に書いた情報が古くならないように、定期的に確認します。

### 5. GitHub Pagesの制約を理解する

GitHub Pagesは静的サイト向けです。

WordPressのような管理画面や動的機能はありません。

できることとできないことを理解して使う必要があります。

## FAQ

### Q1. GitHub Pagesだけでアフィリエイトはできますか？

できます。

ただし、各ASPや広告主の規約、広告掲載ルールを確認する必要があります。

また、広告であることが分かる表記を入れることも大切です。

### Q2. WordPressを使わないと不利ですか？

最初は不利とは限りません。

WordPressは便利ですが、費用や管理の手間もあります。

無料で小さく始めるなら、GitHub Pagesでも十分に実験できます。

### Q3. 何記事くらい作ってからASPに登録すればよいですか？

ASPごとに条件は異なります。

実務上は、プロフィール、広告表記ページ、記事3〜5本程度を用意してから登録すると安心です。

### Q4. GitHub Pagesで広告リンクを貼ってもよいですか？

ASPや広告主の規約に合っていれば掲載できます。

ただし、広告リンクを含む場合は、広告・アフィリエイトリンクを含むことを分かりやすく表示します。

### Q5. AIで記事を自動生成して公開してもよいですか？

下書き作成にAIを使うのは便利です。

ただし、公開前には人間が必ず確認するべきです。

特に、広告表記、商品情報、価格、成果条件、誇大表現には注意が必要です。

### Q6. GitHub PagesのURLでASP登録できますか？

ASPや広告主の条件によります。

GitHub Pages、note、ブログ、SNSなどを媒体として登録できる場合がありますが、必ず各ASPの最新条件を確認してください。

### Q7. 有料サーバーへ移行するべきタイミングはいつですか？

記事数が増え、検索流入やアフィリエイト成果が見え始めた段階で検討すればよいです。

最初から固定費をかけず、無料で検証してから判断するのがおすすめです。
