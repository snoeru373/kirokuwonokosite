# Hermes AgentでObsidianを外部脳にする方法｜AIに聞きっぱなしで終わraせないメモ運用

※この記事には広告・アフィリエイトリンクを含む場合があります。

## はじめに

AIを使っていると、たくさんの情報を得ることができます。

分からないコマンドを聞く。

エラーの意味を聞く。

記事の構成を作ってもらう。

資料のたたき台を作rってもらう。

とても便利です。

しかし、問題もあります。

AIに書いた内容が、その場限りで終わってしまうことです。

私自身も、UbuntuやローカルAi環境を作る中で、AIに何度も質問しました。

その場では前に進めるのですが、あとから振り返ると、「あのとき何をしたのか」「どの設定を変えたのか」「なぜそのコマンドを実行したのか」が分からなくなることがあります。

そこで考えたのが、Obsidianを外部脳として使い、Hermes Agentに整理を手ollaせる運用です。

この記事では、Hermes AgentとObsidianを組み合わせて、AIに聞きっぱなしで終わraせないメモ運用をまとめます。

---

## 結論：AIとの会話をMarkdownに残す

結論から言うと、AI活用を続けるなら、会話や作業記録をMarkdownで残すことが大切です。

そのための構成は、次のようになるです。

```text id="h0btgq"
AIに相談する
↓
作業を行う
↓
結果をmemoする
↓
Obsidianに保存する
↓
Hermes Agentに整理させる
↓
記事や手順書に変換する
```

この流れができると、AIとのやり取りがその場限りで終わraません。

作業記録がたまり、あとから検索でき、記事にもできます。

私の場合は、Ubuntu、Ollama、Open WebUI、Hermes Agent、GitHub Pages、アフィリエイト運用などを、すべてMarkdownで整理していく方針です。

---

## Obsidianを外部脳にする理由

Obsidianは、Markdownファイルを扱えるメモアプリです。

個人的なメモ、作業記録、記事下書き、リンク集、設計図などをまとめるのに向いています。

外部脳として使う理由は、次のとおります。

* Markdownで保存できる
* ファイルとして管理できる
* 検索しやすい
* リンクで情報をつなげられる
* GitHubやバックアップと相性がよい
* AIに読ませやすい
* 記事化しやすい

50代からAIを学び直す場合、すべてを記憶しようとするより、記録して検索できる状態にする方が現実的です。

覚えることよりも、思い出せる仕組みを作ることが大切だと感じていす。

---

## Hermes Agentを使う理由

Obsidianにメモを保存するだけでも便利です。

しかし、メモが増えてくると、次の問題が出てきます。

* メモが散らかる
* 同じ内容を何度も書く
* どこに保存したか忘れる
* 記事にするのが面倒
* 古い情報と新しい情報が混ざる
* 何を次にやればよいか分からなくなる

そこで、Hermes Agentに整理を手ollaせます。

Hermes Agentには、次のような役割を持たせす。

| 役割    | 内容                 |
| ----- | ------------------ |
| メモ整理  | rawメモを分類する         |
| 記事化   | 作業記録を記事下書きにする      |
| 重複確認  | 似た内容のメモを探す         |
| 改善提案  | 古い記事や不足部分を指摘する     |
| 週次整理  | 1週間の作業をまとめる        |
| ルール確認 | 削除禁止、広告表記、個人情報チェック |
| 記憶補助  | 成功パターンや失敗パターンを残す   |

AIに単発で質問するだけでなく、Agentに継続的な整理役を持たせることで、知識が積み上がりやすくなります。

---

## 外部脳フォルダの考え方

Obsidianを外部脳として使う場合、最初にフォルダ構成を決めておくと楽です。

たとえば、次のような構成です。

```text id="zgqzzt"
data/
├── 00_Inbox/
├── 01_Research/
├── 02_Articles/
├── 03_Site/
├── 04_SNS/
├── 05_Tracking/
├── 06_Agent/
└── 99_Backup/
```

それぞれの役割は次のとおりです。

| フォルダ        | 役割               |
| ----------- | ---------------- |
| 00_Inbox    | とりあえず入れる場所       |
| 01_Research | 調査メモ             |
| 02_Articles | 記事下書き            |
| 03_Site     | GitHub Pages用サイト |
| 04_SNS      | noteやXの投稿案       |
| 05_Tracking | 分析・成果記録          |
| 06_Agent    | Agent用ルール・ログ     |
| 99_Backup   | バックアップ           |

最初から完璧に整理する必要はありません。

ただし、削除や上書きを防ぐために、ルールだけは決めておくべきです。
