# Hermes AgentでObsidianを外部脳にする方法 — 手順と注意点

※この記事には広告・アフィリエイトリンクを含む場合があります。

## はじめに：AIに聞いたことを「そのまま」にしないために

私自身、Ubuntuでエラーに出くわすたびにChatGPTやClaudeに質問していました。「これで解決した！」その時は前向きですが、1週間後、「あの時どうやったっけ？」と再び同じ質問を繰り返す。このループが非常に非効率だと感じていたのです。

ここで考え出したのが、**Obsidianを「外部脳」として使って、AIとの会話や作業記録を必ず残し、Hermes Agentで整理させる** という運用です。

この記事では、実際に私が構築したBrain3 Vaultの構成と、Hermes Agentとの連携手順、ハマりポイントをリアルな体験ベースにまとめます。

---

## TL;DR（結論）

> AIとの会話を記録する → Obsidianに保存 → Hermes Agentで整理・記事化 → 改善サイクルに入る
> 
> これにより、一度の学習が資産になり、同じ失敗を繰り返さなくなります。

---

## なぜObsidianなのか — 外部脳としての理由

Obsidianを選んだ理由はシンプルです。**「Markdownファイルとして保存できるから」**。

| メリット | 説明 |
|---------|------|
| ファイルベース | データが外出し可能。Cloudsyncしても大丈夫 |
| リンク機能 | ノード同士を `[[キーワード]]` で繋げられる |
| プラグイン拡張 | ダッシュボード、カレンダー、検索など強化可能 |
| AIとの相性 | MarkdownならHermes Agentも楽に読める |
| 無料版で十分 | デスクトップ版は永久無料 |

「AIの出力 → その場限り」を避けるには、**テキストファイルとしての永続性**が不可欠でした。NotionやEvernoteだとAPI縛りがありますし、純粋なテキストエディタだけでは整理の手間がかかります。Obsidianはその中間点にあります。

## 私が実際に構築したBrain3 Vaultの構成

50代からのAI活用において、最初から完璧なフォルダ構成を作る必要はありません。ただ、「削除しない」という原則だけは決めておくべきでした。

私の環境：GMKtec EVO-X2 AI (96GB VRAM / 48GB) + Ubuntu 24.04 + Obsidian Desktop

```
Brain3/
├── AGENTS.md          ← エージェントに渡す主指示（最重要）
├── SOUL.md            ← 人格・価値観定義（参照専用）
├── brain3-rules.md    ← Brain3統合ルール
├── master-index.md    ← マスターインデックス
├── blog-writing-rules.md  ← ブログ執筆ルール
├── raw/               ← 【原則編集禁止】生データ投入場
│   ├── blog/          ← ブログ素材・作業ログ
│   ├── inbox/         ← 人間が書き込む未整理ネタ場
│   └── archive/       ← アーカイブ済みクリップ
├── wiki/              ← 【AI更新可能】整理済み知識
│   ├── answers/       ← Q&Aノート
│   ├── articles/      ← 記事草稿・完成物
│   ├── concepts/      ← 概念定義ノート
│   └── sources/       ← 出典・情報源ノード
├── _agent/            ← 【AI管理領域】
│   ├── logs/          ← 作業ログ（日次・運用）
│   ├── reports/       ← レポート出力
│   ├── backups/       ← 変更前バックアップ
│   ├── memory/        ← 長期記憶・判断履歴
│   └── tasks/         ← 未完了タスク
└── _daily/            ← デイリーノート（日記風）
```

**重要な注意点:** `raw/` フォルダの中身は絶対に消したくありません。ここに書いた情報はお金では買えません。だから、エージェントが誤って書き換えないよう、「raw = 編集禁止」というルールをAGENTS.mdに明記しています。

## Hermes Agentとの連携手順（実際のセットアップ）

### ステップ1：Obsidian Vaultの準備

まず、Brain3フォルダをObsidianで開きます。

```bash
# Obsidianインストール（Ubuntu向けのSnap版）
sudo snap install obsidian --classic
```

Obsidianを開いたら、「Open folder as vault」で `/home/ubun/Documents/AI-Operations/Brain3` を選べば完了です。

### ステップ2：Hermes Agentのプロファイル設定

Hermes AgentにVaultの場所を教えておきます。これは一度だけやる設定です。

```bash
# Brain3 Vaultのパスをエージェントに教える
hermes config set brain3.vault.path /home/ubun/Documents/AI-Operations/Brain3
```

これにより、AgentはVault内の構造やルールファイル（AGENTS.md）を理解した上で動くようになります。

### ステップ3：連携テスト — デイリーノートの生成

正しく連携できているか確認します。実際にデイリーノートを作ってみましょう。

```bash
# デイリーノートを自動生成するコマンドを実行
hermes chat --workdir /home/ubun/Documents/AI-Operations/Brain3 -s daily-note-system -q "morningモードでモーニングブリーフを作成"
```

成功すると `_agent/outputs/briefings/` にデイリーのファイルが作成されます。Obsidian側でも確認してください。

### ステップ4：実運用のループ開始

1. 新しい情報を得たら → `raw/inbox/` にMDファイルを投げる
2. Hermes Agentに「分類せよ」と伝える
3. Agentは wiki/articless/ や Wiki/concepts/ に配置し、リンクを貼る
4. 毎週日曜日に統合レポートが出される

## ハマりポイント（実際の失敗体験）

### ハマリ①：AGENTS.mdがないとAgentが暴走する

最初にBrain3を使おうとした時、AGENTS.mdを入れていなかったらどうなったか。エージェントが「整理します！」といって `raw/` をごっそり消 going しかけました。幸いバックアップ前で止まりましたが、**AGENTS.mdは必須**です。これがエージェントに対する「憲法」になります。

### ハマリ②：フォルダ名の大文字小文字ミス

Ubuntuではパスは大文字小文字が区別されます。`Brain3` と `brain3` を混同して、Hermes Agentが別のディレクトリを指してしまう事件がありました。vaultパス指定時は常に実際のls出力と照合すべきです。

### ハマリ③：バックアップの取り忘れ

Wiki化の最中、矛盾を見つけた時にバックアップを取っていなくて、前の状態に戻せなかったことがあります。修正前には必ず `_agent/backups/YYYYMMDD_HHMMSS_説明/` に全ファイルコピーしてから変更します。このルールは忘れないようにしています。

## まとめ：一度の失敗を次に活かす仕組み

Hermes Agent + Obsidianの組み合わせが本当に価値を出し始めるのは、最低でも2〜3週間使ってからです。最初の1週間は「ファイルが増えるだけ」「なぜ整理するのか分からん」という感覚になります。それが2週間目以降に徐々に"知識資産"になっていきます。

重要なのは：
1. **記録する**（raw/inboxに何かを入れる）
2. **整える**（Agentに wiki/ へ配置させる）
3. **振り返る**（週次レポートで何が変わったか確認する）

このルーティンを1ヶ月続けられると、必ず「あの時のメモどうしたっけ？」というストレスが減ります。

50代からのAI活用において、知識の積み重ねが最大の武器です。外部脳を作って、それをAgentに整理させる。これが最も早く回ってくる投資だと思います。

## FAQ（よくある質問）

### Q1. ObsidianとHermes Agentを組み合わせないのはダメですか？

いいえ、どちらだけでも使えます。ただし、メモが増えてきた時に「どこに保存したっけ？」というのは人間なら誰しも経験のあること。Agentを使って整理することで、そのストレスが大きく減ります。

### Q2. エージェントに全部任せて大丈夫ですか？

全て自動化すべきではありません。記事の公開・削除、広告リンクの掲載、個人情報を含むファイルの処理は、最終判断を人間が行うべきです。エージェントは補佐役です。

### Q3. Obsidianを複数デバイスで使えますか？

使えます。Obsidian自体が同期プラグインやSyncサービスに対応しています。Brain3 VaultもGit経由でバックアップ可能です。

### Q4. 最初から完璧な構成にする必要がありますか？

全く必要ありません。まずは「rawに突っ込む → Agentが整理する」の1サイクルだけで十分です。後は使ってみながら段階的に増やしていきましょう。
