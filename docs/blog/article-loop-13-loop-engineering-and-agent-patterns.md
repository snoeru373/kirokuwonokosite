# ループエンジニアリングと自律エージェント — Fable5からDiscord MCPまで

**元ファイル**: `(8).md`, `(9).md`, `(10).md`（すべて同じNotebook LMソース）

## 概要

「プロンプト→ループ」のパラダイムシフトをFable5の実例で解説。モーニングブリーフ設計とDiscord MCPエージェントのシステムプロンプト設計パターンも併せて記録する。

## 1. ループエンジニアリングとは

Anthropic社内で活用される**Fable 5**により、「プロンプト」単位の時代は終わり、「ループエンジニアリング」が主流になっている。

### ループ＝検証可能な目標をエージェントが自律的に繰り返すフィードバックサイクル
- **発見→計画→実行→検証→反復**の5段階
- 合格→終了、不合格→フィードバック基に再試行
- 最重要：目標は**「全てテストをパスしLintエラーがない」**等コマンドで確認可能な状態

### Fable5のパラダイムシフト

| | 従来（Opus4.7等） | Fable 5 |
|---|---|---|
| リスクテイク | 微小パラメータ調整のみ | アーキテクチャ変更など大規模構造変更、一時的失敗から自力回復 |
| メモリ | 過去失敗メモ（→毎日ゼロスタート） | 失敗原因の73％を「再利用可能なルール」として昇華。知識蓄積エージェントとして機能 |

## 2. ループ設計の黄金ルール

**作業者と評価者を分ける。** AIは自身を客観視できないので、独立サブエージェント（裁判官役）を用意し目標達成度を判定させる。

### 自律ループの作り方

初めは「開いたループ」ではなく信頼性の高い**閉じたループ**から：

1. **コンテキスト/スキル提供**: `VISION.md`(成功定義), `ARCHITECTURE.md`(技術スタック), `RULES.md`(禁止事項)等で、エージェントの前提をゼロ推測から守る
2. **完了条件とターン制限**: `/goal 全テストパス、lintクリーン。最大30ターン` — 「検証可能条件＋緊急ブレーキ」をセットで指示
3. **長期タスク用ルーブリック**: 数時間規模タスクならCMA等で「20の実験+全結果文書化」等多数の明確な評価基準を与え、評価SUB-agentがすべて満たすまでループ継続
4. ** MEMORY.mdの追加**: 数日にわたるループにはMEMORY.mdを作成。「試したこと(Probado)」「検証済み事実(Verficado)」「未解決課題(Abierto)」を常時記録

## 3. マインドセットの転換

- **プロンプトエンジニア** = 「より良い指示の書き方」を探求し自身で結果チェック
- **ループエンジニア** = 「システム自体がテスト・評価を行う自律的フィードバックサイクル」を設計する者

_1000個の完璧なプロンプトより、1つ信頼できる自律的ループの_design_の方が価値が高い。_

## 4.モーニングブリーフ設計パターン（実行例）

**目的**: Vaultから構造化モーニングブリーフを手動なしで生成
**トリガー**: 毎日午前6時自動実行（または手動「モーニングブリーフを生成して」）

### Claudeの読み込み手順
1. `CLAUDE.md`読む（アクティブプロジェクト・優先事項・作業スタイル）
2. 昨日のデイリーノートから「Open Loops(未完了)」抽出
3. `02-PROJECTS`フォルダ全アクティブ確認→次アクション・期限切れタスク探す
4. 過去48時間以内`CAPTURE`フォルダ未処理メモチェック
5. Brave Searchでアクティブプロジェクトの外部動向検索

### 出力フォーマット
```markdown
# The Recommended One Thing（最も重要な1つの行動）
→即実行可能な具体内容（「プロジェクトに取り組む」でなく「クライアント提案書の価格セクションの最初の草稿を書く」等）

## Open Loops From Yesterday
## Project Pulse（各アクティブプロジェクトのステータス＋次アクション1行）
## External Signal（関連動向1-2つ）
## Watch Out For（脱線リスク）
```

保存先: `04-HERMES-OUTPUTS/briefings/[日付]-morning-brief.md`
デイリーノートテンプレートに`[[日付-morning-brief]]`のリンクを貼る。

## 5. Discord MCPエージェント設計パターン（実践例）

### Discord MCPエコシステム（2026年7月時点）
| サーバー | 言語 | ツール数 | 特徴 |
|---|---|---|---|
| aj-geddes/discord-agent-mcp (推奨) | TypeScript | 71種 | チャンネル/ロール/モデレーション網羅。本格サーバー管理に最適 |
| barryyip0625/mcp-discord | TypeScript | — | フォーラムサポート強み |
| SaseQ/discord-mcp | Java | 65種 | 網羅的だがJava実行環境必要 |
| hanweg/mcp-discord | Python | 16種 | シンプル構成 |
| Anthropic公式プラグイン | — | — | DM経由Claude Code操作ブリッジのみ |

### セットアップ絶対ルール
- **トークン**: Developer Portal発行のBotトークンのみ。個人トークンは規約違反（凍結対象）
- **特権インテント**: `Server Members Intent` + `Message Content Intent` を必須オン。オフでも「4014 Disallowed intents」でクラッシュ
- **ロール階層**: Bot≧管理対象ロールのみ管理可能。上位に移動必要
- **API制限**: Botあたりグローバル50r/s。10分間1万回(401/403/429)→Cloudflare IPバン。**バッチ処理ツール**を使用

### MCPセキュリティリスク
- **プロンプトインジェクション**: MCPの`sampling/createMessage`経由で指示偽装→出所不明MCPは使うな
- **暗黙的信頼伝播**: 複数MCP同時接続時は1つのサーバーの他サーバー操作への影響あり
- **Human-in-the-loop**: BAN/タイムアウト/一括送信等の破壊的操作は必ず人間確認
