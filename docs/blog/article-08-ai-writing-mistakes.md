## TL;DRの結論

> AIで記事を書く際、最も大切なのは「AIの出力をそのまま公開しない」こと。虚偽、誇張、個人情報漏洩が最も怖いミスです。
> ここでは私が経験したNG事例10選をまとめます。

## やっちゃダメだ! 失敗パターン Top 10

### NG① — AIに嘘をつくよう促す（プロンプト設計の誤り）

```yaml
# ダメな例:
「最新の2026年X月のデータを調べて」
→ その情報がない場合、AIは事実を補います。嘘が出力される。

# 良い例:
「もし情報がない場合は『現在正確なデータがありません』と答えてください。」
```

### NG② — 生成された記事をそのまま公開する

- AIの答えには必ず校正を入れる
- 自分の言葉で書き換える（特に体験談部分）

### NG③ — 引用先URLを指定しない

「Wikipediaの記事によると...」と書いているのに、リンクも出典もないものは SEOにダメージ。
→ 必ず具体的な出典URLと確認日を入れる。

### NG④ — プライバシー情報（住所・電話番号等）を含むデータをAIに入力する

- Cloud AIの場合、入力データが学習に使用される可能性あり
- ローカルAIの場合、ファイルが残るのでバックアップも考慮

### NG⑤ — アフィリエイト規約違反のリンクを貼る

- Amazon, A8.NET等の規約を確認せずにURLをAI生成させる
- 必ず自分でURLを再確認する

### NG⑥ — 専門的知識が必要な話題にAIだけを頼りにする

- 医療・金融などのトピックでは、専門家チェックを入れよ
- 「私の知る限り」で十分という立場は明確にする

### NG⑦ — SEOのためにAIにキーワード stuffing を要請する

```yaml
# ダメな例:
「ubuntu ローカル AI ubuntu おすすめ ubuntu ローカル」という言葉を10回入れて」
→ 検索エンジンが懲罰的にペナルティ付与する場合があります。
```

### NG⑧ — 画像生成AIで著作権違反のクリエイター名を入れる

CanvaやDALL-Eの「このクリエーター風にして」という指示はNGです。

### NG⑨ — バックアップなしでAIにファイル削除をさせる

- `rm -rf` は禁止！mvやrmdirが安全
- 変更前には必ずバックアップコピーを作成

### NG⑩ — AIの応答を「事実」のまま信用し検証しない

最も危ないミス。AIの情報は何でも鵜呑みにすると:
1. 古い情報が最新と偽られる（date hallucination）
2. 存在しないURLが生成される（リンクビッチ)
3. モデル名やバージョン番号が嘘になる → **必ず出典URLで確認する**

## 私が実際に失敗した例

### 失敗事例1: バージョン番号の誤情報

「Ubuntu 25.04LTSには次の問題があります」とAIに出力させましたが、実際は24.04 LTSしかありませんでした。
→ **対策**: 各バージョン番号を公式サイトで確認してから引用する。

### 失敗事例2: API Keyの漏洩

ChatGPTのプロンプト内に自分のAPIキを貼り付けたことにより潜在的に第三者にも情報が流れてしまう可能性があります（過去の実体験）。
→ **対策**: APIキーはプロンプトに入力せず、`.env`ファイル経由で安全に取り扱う。

### 失敗事例3: Canvaの有料要素混入

Canvaの無料テンプレートに思っていたら一部がPro(有料)だったため、公開できないという事態になりました。
→ **対策**: DL前に必ずフィルタで「無料のみ」をオンにする。
