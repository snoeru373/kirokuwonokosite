## 要約（全文）

Claude Codeチームは、**ループを「エージェントが必要な停止条件を満たすまで作業サイクルを繰り返す仕組み」**と定義しています。これは単なるプロンプトではなく、意図的に設計するものとして捉えるのが最近のトレンドです。

ループはいくつかの基準で分類されます：

- **トリガー方式**: 誰がループを開始するか
- **終了条件**: ループをいつ止めるか
- **Claude Codeのプリミティブ**: どのAPI/コマンドを使うか
- **適したタスクの種類**

複雑すぎるループは不要です。最初はシンプルに始めて、パターンを選択的に適用していくのが推奨されます。

## Claude Codeが定義する主要なループ类型

### 1. トurn-based ループ

最も基本的なタイプで、ユーザープロンプトによって開始され、Claude自身が必要か判断して終了します。比較的小規模タスクに適しています。

- **トリガー**: ユーザーのプロンプト
- **停止条件**: Claude「タスク完了」と判断または追加情報が必要と判断
- **向きな用途**: ショートタスク、定期プロセスではないもの
- **コスト管理技巧**: SKILL.mdで手動手順をエンコーディングし、Claudeにより多くの自己チェックをさせる

### 2. SKILL.md経由の自己検証

重要なアイデアとして「手動のステップ」をSKILL.md中にエンコーディングしてClaudeが自身で検出できる仕組みがあります：

```
例: verify-frontend-changeスキル — Frontend変更を検証する際：
1. dev server起動 → ブラウザでページ確認
2. アイテムとのインタラクション（スクショ比較）
3. browser consoleのエラーチェック
4. Devtoolsのperformance trace + Core Web Vitals
すべてのステップがpassした時点でのみ完了扱いにすること。
```

これはつまり、「AIに指示する」のではなく「仕組みを回すループを使う」というパラダイムシフトの核心です。

## AIエージェントのループ思考

この投稿のポイントは、**プロンプトを打つこと」よりも「仕組み（= ループ）を設計すること」**です。

- プロンプト: 「このコードを書いて」 → その場で完結する → エラーがあれば再度プロンプト
- ループ: 「チェックリストに全部passするまで自分で確認して、失敗したら直す」→ 自動反復で品質向上される

つまり「ループ=閉じたフィードバックサイクル」です。AIが「自分で」エラーを検知し、修正し、再検証する仕組みを設計することで、人間の介入回数を削減できます。
